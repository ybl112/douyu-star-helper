# 测试说明

测试代码位于 `tests/`，使用 Node.js内置测试工具、模拟时间、接口响应与工作页环境。

目前69项测试：

1. 按实际金币奖池排序，过滤门槛并优先选择金额最高的红包。
2. 没有符合条件的红包时，不自动降低门槛。
3. 同金额使用稳定排序，不把 `waitSec` 当作剩余时间，并排除已结束或异常红包。
4. 按服务器返回的实际奖励统计到账。
5. 每日上限立即取消所有任务；同日禁止重启，次日需手动启动。
6. 达到自定每日包数后停止。
7. 等待超过5次后仍可继续复查，但受最大时限约束，恢复时避免集中补发。
8. 领取请求超时后停止，避免盲目重复提交。
9. 已派完的红包跳过，不终止其他任务。
10. 鉴权失败、要求验证或异常响应时停止。
11. 停止后忽略迟到的房间查询结果。
12. 较慢的房间发现不阻塞到时间的领取任务。
13. 并发准备任务不超过设置的后台标签页数量。
14. 刷新候选列表后，已完成的红包保持去重。
15. 动态CSRF映射、北京时间日期与设置范围校验。
16. 空奖励红包计为零收益。
17. 连续三轮查询失败后停止，重试间隔逐次增加。
18. 设置变化后，开页前重新检查候选资格。
19. 启动时已达自定包数上限，就不打开工作页。
20. 只有实际读取的对应红包状态允许领取，单纯经过观看时长不能触发。
21. 前5次尚未就绪，第6次仍能正常领取成功。
22. 接口重复返回完整 `waitSec` 时不会无限延后截止时间。
23. 收到 `12006` 后复查，识别已结束的红包。
24. 红包短暂消失时二次确认，并保留重新检查机会。
25. 升级后恢复旧版本误标记为已处理的超时红包，保留真实成功记录。
26. 进入活动前完成官方入口登记。
27. 入口登记提示上限或登录失效时，不打开工作页。
28. 工作页命令只传递红包ID，匹配对应请求的响应。
29. 停止任务时取消工作页请求并移除监听器。
30. 工作页响应超时后清理请求，避免重复下发。
31. 工作页从当前房间获取最新红包标识后再提交。
32. 工作页回传保留业务状态与奖品，移除领取标识和凭证字段。
33. 工作页读取官方红包节点的实际秒数，不自行递减或估算。
34. 实际工作页适配代码对同一命令只提交一次，使用对应房间及本地凭证。
35. 任务撤销后关闭对应工作页，不继续发出请求。
36. 独立版本检查文件与安装脚本头部完全一致，且不包含执行代码。
37. 脚本、版本检查文件、项目配置与README版本号保持一致。
38. 更新地址、下载地址及脚本标识正确，版本查询仅允许访问固定更新域名。
39. 手动更新入口仅在点击后打开固定安装地址，不修改已有设置或发出业务请求。
40. 版本号按数字比较，拒绝异常版本格式。
41. 版本信息必须属于本脚本，拒绝错误脚本、HTML或附加执行代码。
42. 版本查询只读取固定版本文件，不携带Cookie，成功后清理超时计时器。
43. HTTP错误、异常跳转和错误响应不误报为最新版。
44. 独立截止计时能取消无响应的检查，并忽略迟到结果。
45. 网络失败、权限拒绝与油猴超时后可重新检查，并清理计时器。
46. 两种状态的位置均限制在窗口内，兼容异常存储值与较小窗口。
47. 拖动期间移动位置，松开后才保存，并阻止拖动引发的点击。
48. 普通点击和轻微抖动不误识别为拖动。
49. 忽略子控件、非主按键、其他指针和多点触摸干扰。
50. 指针取消或捕获丢失后结束拖动，下一次拖动不受影响。
51. 拖动防误触不阻止键盘点击，且会及时失效。
52. 页面尚在倒计时时，即使收到领取命令也不发请求。
53. 其他红包的命令不能借用当前红包的可领取状态。
54. 发送命令前状态丢失时暂停，不误停所有房间。
55. 刷新红包标识期间撤销任务，迟到结果不能触发领取。
56. 房间查询返回后再次检查页面，倒计时变化时不提交。
57. 初始化CSRF期间停止，也不会发出最终领取请求。
58. 读取节点必须精确匹配红包ID，重复读取不会自行扣减秒数。
59. 仅原生领取按钮代表可领取；缺失、隐藏及异常文字不当成零秒。
60. 过期、未来时间、身份不符和状态矛盾的观察结果无效。
61. 生产脚本不保留比例估算或按重试时间生成倒计时的代码。
62. 兼容官方字符串化奖品数据，不把错误格式当成领取成功。
63. 一个领取请求卡住，不阻塞另一个房间处理实际状态。
64. 自定每日包数为进行中的领取预留名额，并发时不超额提交。
65. 连续等待回复保持2秒复核，不递增至30秒。
66. 错误红包与过期状态既不提交领取，也不显示估算值。
67. 房间发现阶段提示鉴权、风控或每日上限时立即停止。
68. API固定等待字段较长时，不误过滤实际剩余时间已符合设置的红包。
69. 最长等待设置以页面实际秒数校验。

## 面板交互检查

另在隔离的 Chrome 页面中运行实际脚本，使用模拟油猴存储和版本响应，检查版本按钮、新版提示、重复点击、错误恢复、安装入口、两种状态拖动、位置分别保存及刷新恢复、拖动防误触和300像素宽窗口布局。检查期间不登录账号、不提交领取请求。

2.0.4另验证了真实DOM变化监听：官方样式的对应红包节点从73秒变为11秒时直接读取新文字，切换为原生领取按钮后才允许模拟请求；撤销任务后关闭对应工作页。全流程检查记录见 [2.0.4检查记录](REVIEW-2.0.4.md)。
